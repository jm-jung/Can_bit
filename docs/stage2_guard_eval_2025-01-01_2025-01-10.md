## 코드 구조 분석 (실행 불가 시 대체 분석)

### Stage-2 + Guard 상호작용 흐름

1. **신호 생성 단계** (`generate_signals()`)
   - Stage-2가 활성화되면 `stage2_trade` 배열 생성
   - `stage2_trade[i] = True/False`로 거래 여부 판정
   - 최종 signal: `final_signals = np.where(stage2_trade, signals, "HOLD")`

2. **트레이드 실행 단계** (`execute_trades()`)
   - 각 row 처리 시:
     - `stage2_trade` 값을 읽음
     - Guard가 활성화되면:
       - `guard.update_signal(stage2_trade=stage2_trade, ...)` 호출
       - `guard.check()` 호출하여 ALLOW/BLOCK 판정
       - BLOCK이면 `signal = "HOLD"`로 변경하고 `continue`

3. **트레이드 완료 시**
   - `guard.update_trade(profit=..., ...)` 호출하여 성능 기록

### 예상 동작

**케이스 2 (Stage-2 only):**
- Stage-2가 낮은 확신 신호를 필터링하여 거래 수 감소 예상
- `stage2_trade_th=0.58`, `stage2_min_edge=0.05` 조건으로 인해 일부 신호만 통과

**케이스 3 (Guard only):**
- Guard가 최근 20개 트레이드 성능을 모니터링
- `win_rate < 0.4` 또는 `avg_return < -0.01`이면 BLOCK
- BLOCK 후 최소 5개 트레이드 경과 후 UNBLOCK 조건 체크

**케이스 4 (조합):**
- Stage-2가 먼저 신호를 필터링
- Guard가 Stage-2를 통과한 트레이드의 성능을 모니터링
- 두 단계 필터링으로 인해 거래 수가 더욱 감소할 수 있음
